# CLI daemon subcommand integration

The commit adds a `daemon` subcommand to the CLI that invokes the existing `run_daemon()` function from the daemon module. This fixes the systemd service's exit code 2 error, which was caused by the CLI not recognizing `daemon` as a valid subcommand. The fix is minimal: a new argument parser for the daemon subcommand, a command handler that calls `run_daemon()`, and registration in the command dispatch table.

**Watch for:** None. The implementation is correct — parameter names align with the daemon function signature, the handler is properly registered, and the spot-check confirms the daemon command now exits 0 instead of 2.

**Verdict**: APPROVED

## High-level view

The daemon subcommand is registered in the argument parser with four optional flags: `--dir` for the applications directory, `--no-notify` to disable notifications, `--no-dialogs` to disable dialogs, and `--dev` for development mode. The `cmd_daemon` handler translates these CLI arguments to the parameter names expected by `run_daemon()`: `applications_dir`, `no_notify`, `no_dialogs`, and `dev_mode`. The handler is added to `COMMAND_HANDLERS` so the CLI dispatcher can route `appimage daemon` to it.
